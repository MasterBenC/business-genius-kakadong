# 本地知识库挂载（miit-qualification-kb）

卡卡东的商业体检与投资人 BP **不**把工信 / 科技认定当作自动加分或自动「可继续」依据。高新技术企业、专精特新 / 小巨人、制造业单项冠军、行业领军等，只能作为**证据维度**：有可核对的公示名单、证书摘要或用户提供的脱敏材料时标 `occurred` / `material`；仅有口头主张时标 `to-validate`。私库 `MasterBenC/miit-qualification-kb` **不随本 Skill 公开发布**，本文件只说明挂载与引用约定。

## 何时打开

仅当用户话术、材料或 BP 叙事触及下列主题时，先读本文件再按需打开库内路径：

- 高新技术企业认定办法 / 工作指引 / 重点支持领域
- 创新型中小企业、专精特新中小企业、专精特新「小巨人」
- 制造业单项冠军
- 行业领军（见下方 PENDING 规则）
- 申报材料清单、常见否决项、地方特色化指标
- 「我们是不是高新 / 专精特新」类资格核对

常规产品、买家、价格、交付体检**不默认**挂载本库。挂载失败时：继续做商业判断；凡拟引用认定办法条文、指标阈值或认定状态处，统一标记 `needs_verification`（或核验失败时的 `unavailable`），**禁止编造文号、条文、认定结论或公示名单**。

## 宿主如何挂载

任选其一（建议优先级从上到下）：

1. 环境变量 `MIIT_QUALIFICATION_KB_ROOT` 指向 `miit-qualification-kb` 仓库根（含 `_index.md` / `AGENTS.md` 的那一层）。
2. 与本仓库或 Skill 目录同级的 sibling 克隆：`../miit-qualification-kb`。
3. 宿主配置中声明的绝对路径。

可选二级库（**仅当**用户同时追问高新税收优惠、加计扣除等税务路径时再挂；资格事实仍须客户确认或主体库命中，不得因税口径命中而自动认定已获高新）：

- `PERSONAL_KB_ROOT` 或 sibling `../personal-kb` → 私库 `MasterBenC/personal-kb` 的 `02-税务/部门规章与规范性文件/` 中高新相关篇。

## 读取顺序

1. 打开 `miit-qualification-kb/_index.md` 与 `AGENTS.md`，确认域目录。
2. **只打开任务所需子目录**；禁止默认加载整个仓库，尤其不要把 `03-企业主体库/`、`04-人物库/` 整库塞进上下文。
3. 再按下方主题表打开具体文件。

## Citation format / 输出中的引用格式

对从知识库读到的办法、指标或主体档案，在体检报告或 BP 说明中写：

```text
依据：miit-qualification-kb/<相对路径>#条号或标题
来源状态：kb | verified | needs_verification | unavailable
```

状态含义（与证据标签配合）：

- `kb`：已从已挂载 `miit-qualification-kb` 读出；适合内部分析与草稿。对外申报辅导、尽调备忘或正式 BP 中的认定主张，应再经官方名单 / 现行文件升级为 `verified`。
- `verified`：已通过工信部优质中小企业梯度培育平台、单项冠军培育平台、科技部 / 省级公示或官方发布页核验。
- `needs_verification`：尚未完成库检索或官方核验；知识库未挂载、PENDING 占位或主体未入库时强制使用。
- `unavailable`：核验失败或无法取得可靠来源。

商业证据标签仍用 `occurred` / `material` / `to-validate`：库内政策条文命中 ≠ 客户已获认定；只有用户提供的公示 / 证书脱敏摘要或主体库已核条目，才能把「已获 XX 认定」标为 `occurred` 或 `material`。

## Hard rules / 硬规则

1. **禁止编造认定状态或称号。** 企业是否高新 / 专精特新 / 小巨人 / 单项冠军，只能依据 `03-企业主体库` 已录入且带来源的条目，或用户当场提供的可核对脱敏材料；人物称号同理看 `04`。
2. 库内没有的，回答「未入库」，并提示查官方培育平台或省级公示，**不要猜测**。
3. `PENDING-*.md` 表示正文未齐，**不得当作有效办法或指标引用**。
4. 知识库命中**不能**单独把体检结论抬升为 `continue`，也**不能**在投资人 BP 中写成已获认定的既成事实（除非证据状态支持）。
5. 对伪造认定证书、虚构公示名单或用虚假资质融资的请求，走 Skill 的 Safety refusal path，不生成优化话术。

## If KB is missing / 知识库未挂载

- 明确告知用户 `miit-qualification-kb` 不可用。
- 仍可完成不依赖认定条文的商业体检与 BP 骨架。
- 凡拟依赖认定办法、指标阈值或「已获认定」主张处，标记 `needs_verification` / `to-validate`。
- **Do not invent policy text or qualification status.**

## Sync / 时效声明

`miit-qualification-kb` 底稿可能滞后于工信 / 科技 / 省级主管部门现行文本与公示名单。正式申报、尽调、对外意见或融资材料引用前，须对照官方现行文件与名单复核，并将状态升级为 `verified`（记录机关、文号或公示期、URL、核验日期）。
